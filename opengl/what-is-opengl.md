# OpenGL이란?

이제 기나긴 여정을 시작하기 전에,
아무것도 모르는 상태로 할순 없으니 먼저 **OpenGL**이 뭔지 알아보겠습니다.
흔히 OpenGL은 그래픽과 이미지를 조작하는 데 사용할 수 있는 다양한 기능 세트를 제공하는 **API**로 말하는데,
그러나 OpenGL 자체는 API가 아니라 단지 [크로노스 그룹](https://www.khronos.org/)이 개발하고 유지 관리하는 사양일 뿐입니다.

OpenGL 사양(표준이나 스펙이라고도 불러요. 아마도.)은 각 함수의 결과와 출력, 그리고 실행 방식'만' 명시하는데요,
따라서 이 사양을 어떤 방식으로 구현하는지는 온전히 **개발자의 몫**입니다.
게다가 OpenGL 사양은 정확히 어떻게 해야하는지를 알려주지 않으므로, OpenGL이 사양을 준수하여 동일한 결과를 제공한다면, 실제 구현 방식은 서로 다를 수 있습니다.

그러면 실제로 동작하게 해주는 프로그램도 크로노스 그룹이 만들까요?
정답은 "아니요"입니다.
OpenGL 라이브러리를 만드는건 보통 그래픽 카드 제조사가 하는데요,
(개발자가 일일히 할순 없잖아요 ㅎ)
예를 들어 Apple 기기(맥북 등)를 사용할땐 OpenGL 라이브러리는 Apple에서 직접 관리합니다. 따라서 OpenGL이 이상하게 작동한다면, 그건 그래픽 카드 제조사의 잘못일 가능성이 큽니다.

> tip! 앞에서 라이브러리를 그래픽 카드 제조사가 한다고 했죠? 그래서 유지보수도 제조사들이 합니다. 오류가 날땐 드라이버를 업데이트 해보세요! 대다수는 여기서 해결될겁니다.

크로노스 그룹에서는 모든 OpenGL 버전의 **문서**를 공개하고 있습니다. 관심 있으면 [OpenGL 버전 3.3 문서](https://registry.khronos.org/OpenGL/specs/gl/glspec33.core.pdf)를 읽는 것을 강추드립니다. (이 글에서 쓰는 버전입니다) 그 문서는 자기들이 직접 만든걸 설명하기에 OpenGL의 작동 원리를 깊이 이해하고 싶은 사람들에게 아주 좋은 참고 자료입니다. (하지만 보통 구현 결과를 설명할뿐 구현 방식은 제공하지 않습니다. ㅜㅜ 그 사람들도 구현까지 적기는 귀찮았나봐요)

## Core-profile vs Immediate mode

--왜 Core만 profile이고 Immediate는 mode냐는 의문이 드실수도 있습니다만 그건 그들이 정해서 설명이 불가능합니다 ㅋㅋ--

예전에는 OpenGL을 사용할 때 주로 immediate mode(즉시모드라고 할게요)를 사용했습니다. 이는 흔히 fixed function pipeline이라고도 불렸는데, 그래픽을 그리기 위한 간단하고 직관적인 방법이었습니다. 당시에는 대부분의 OpenGL 기능이 라이브러리 내부에 숨겨져 있었기 때문에, 개발자는 OpenGL이 어떻게 계산하는지에 대한 제어권이 거의 없었습니다.
하지만 시간이 지나면서 개발자들은 더 많은 유연성을 원하게 되었고, (아마 그들은 엄청난 변태일겁니다. 확실히요.) 이에 따라 OpenGL 명세도 점점 더 유연해졌습니다. 그 결과, 개발자들은 그래픽 렌더링에 대해 더 많은 제어권을 갖게 되었습니다. (그래도 Vulkan에 비해선 아무것도 아니죠)

즉시 모드는 배우고 사용하기는 매우 쉬웠지만, 성능 면에서는 매우 비효율적이었습니다. 그래서 OpenGL 명세는 버전 3.2부터 즉시 모드 기능을 점차 제거하기 시작했고, 대신 core-profile 모드에서 개발할 것을 권장하게 되었습니다. 이 core-profile 모드는 기존의 오래된 기능들을 제거한 현대적인 OpenGL 모드입니다.

### Core-profile 모드의 특징

- Core-profile을 사용할 경우, OpenGL은 과거 기능을 사용 못하게 합니다.
- 만약 과거 기능들의 함수를 사용하려고 하면, OpenGL은 에러를 발생시키고 렌더링을 중단합니다.
- 현대적인 방식은 매우 유연하고 효율적이라는 장점이 있습니다.
- 하지만 배우기는 훨씬 더 어렵습니다. (오, 이런..)

즉시 모드는 OpenGL이 수행하는 실제 연산에서 많은 부분을 추상화했기 때문에 배우기는 **쉬웠지만**, OpenGL의 실제 작동 방식을 파악하기는 어려웠습니다. 반면 최신 방식은 사용하려면 개발자가 OpenGL과 그래픽 프로그래밍에 이해를 해야 하고, 다소('소'를 빼야 할것 같군요) 어렵기는 하지만 훨씬 더 높은 유연성과 효율성을 제공하고, 그 무엇보다도 ****그래픽 프로그래밍에 대한 이해도를 높여**줍니다.

이 글이 OpenGL 버전 3.3을 기반으로 작성된 이유도 이거입니다.
비록 진입장벽이 높아지더라도, 끝내 배우고 나면 그만한 가치가 충분히 있습니다.
물론 OpenGL 4.x 버전도 있습니다.
이 역시 레거시를 제거한 최신 버전이지만..

1. OpenGL 3.3 이후의 모든 버전들은 기능 추가가 있긴 했어도 기본적인 렌더링 파이프라인과 핵심적인 프로그래밍 방식은 그대로였습니다.
2. 즉, 핵심 기술은 3.3에서도 동일하기 때문에, 비교적 예전 그래픽 카드도 지원할 가능성이 높은 3.3을 고르는게 더 낫지 않을까요?

> tip! 개발자들은 하위호환성을 위해 바로 4.x로 개발하지 않습니다. 3.3을 타겟으로 잡고, 필요할때 조금씩 올리는 방법을 쓰지요.

일부 글에서는 최신 기능이 나올 수도 있는데, 따로 말을 할테니 걱정 마세요.

## 확장 기능

OpenGL 하면 바로 떠오르는 것중 하나가 **확장 기능(extension)** 입니다.
그래픽 카드 회사가 새로운 기술이나 큰 렌더링 최적화, 성능 최적화 기법 등을 개발했을 때,
이런 기능은 종종 드라이버에 포함된 확장(extension) 형태로 나옵니다. 하드웨어가 그 확장을 지원한다면 개발자는 그 확장이 제공하는 고급 기능을 활용해 더 효율적이고 발전된 그래픽 표현을 구현할 수 있습니다.

이렇게 하면 그래픽 개발자는 OpenGL의 공식 버전에 기능이 반영되기를 기다릴 필요 없이 그냥 그래픽 카드가 해당 확장을 지원하는지 확인만 하면 바로 새로운 기술을 사용할 수 있습니다. 가끔 인기있고 유용한 확장기능은 추후 OpenGL 공식 버전의 일부로 포함되기도 합니다.

### 사용 방법

대다수의 개발자들은 확장 기능을 지원하는 그래픽 카드인지 확인합니다.
만약 무조건 확장을 쓰게 한다면.. 지원하지 않는 기기에선 오류가 뿜어져 나오겠죠?

그래서 이 과정을 통해 개발자는 해당 확장이 존재하는 경우 그래픽 처리 작업을 더 효율적으로 구현할 수 있습니다.
예시입니다.

```cpp
if(GL_ARB_extension_name)
{
    // 확장이 있을때! 실컷 확장 쓰세요.
}
else
{
    // 만약 확장이 없다면 옛날 방식으로;;
}
```

이 글에선 확장을 거의 사용하지 않을 예정이지만, 쓰게 된다면 언제든 확장 쓴다고 적겠습니다.

## 상태 머신

OpenGL은 상태 머신입니다.
(물론 GLSL 같은 내용을 들어가면 더 이상 와닿지 않을겁니다..)
그냥 변수들을 묶어놓은 개념이라 보시면 됩니다.
이러한 OpenGL 상태는 ****OpenGL 컨텍스트**에 저장됩니다.
OpenGL을 사용할때 옵션을 설정하고, 버퍼를 수정하고, 현재 상태를 바탕으로 렌더링을 수행하는 등
우리는 자주 상태를 변경하게 됩니다.

예를 들어, 삼각형 대신 선을 그리도록 OpenGL에 지시할 때마다 OpenGL이 그림을 그리는 방식을 설정하는 **컨텍스트 변수**를 변경하여 OpenGL의 상태를 바꿉니다. 컨텍스트를 변경하여 OpenGL에 선을 그리도록 지시하는 순간, 이후의 그리기 명령은 삼각형 대신 선을 그리게 됩니다.

컨텍스트를 바꾸는 함수는 크게 2가지가 있습니다.

1. 상태를 바꾸는 함수(state-changing functions):
OpenGL의 컨텍스트를 변경합니다. 한마디로 상태값 변경입니다.

2. 상태를 사용하는 함수(state-using functions):
현재 설정된 상태를 기반으로 그 함수의 동작을 실행합니다.

**"OpenGL은 하나의 거대한 상태 머신이다"**
라는 진리(?)를 잘 기억하면 됩니다.

> tip! 이해가 하나도 안 가면?
비유를 하자면, 상태값 변경 -> 신호 쏘기입니다.
예를 들어 우리가 철수를 90도 방향으로 움직이게 하고 싶을때,
```cpp
철수.바라보는_각도 = 90;
```
이렇게 상태를 바꾸는 함수를 실행합니다.
이러면 철수는 이렇게 됩니다.

```cpp
철수 {
    바라보는_각도 = 90;
    // 기타 여러 상태들..
}
```

이게 상태를 바꾸는 함수입니다.
```철수.바라보는_각도 = 50;``` 을 하면 철수의 상태값이 또 변하겠죠?

## 객체

OpenGL 라이브러리는 기본적으로 C로 작성됐습니다.
(다른 언어에서도 사용은 가능)
그러나 C의 문법 구조는 다른 고급 언어와 완벽하게 호환되지 않는 경우가 많기 때문에 OpenGL은 이러한 점을 고려해 몇가지 **추상화 개념(abstractions)을** 도입했습니다.
그중 하나가 바로 OpenGL 객체입니다.

OpenGL에서 객체는 OpenGL 상태의 일부를 나타내는 옵션들을 모은건데,
예를 들어 드로우 윈도우의 설정을 나타내는 객체가 있다 하면,
이 객체를 통해 창의 크기, 지원하는 색상 수 등을 설정할 수 있습니다.
객체는 C의 구조체와 비슷합니다.
예시입니다.

```c
struct object_name {
    float  option1;
    int    option2;
    char[] name;
};
```
아니, 왜 C++ 한다면서 C 하냐?
말이 C++지 호환을 위해 문법이 사실상 C이기 때문입니다^^ 예시가 C++ 문법을 거의 안써서 그랬습니다. (번역하는 저도 정말 힘드네요.)

이제 객체를 사용할 때 보통 이렇게 보입니다. (OpenGL 컨텍스트가 이제 하나의 구조체로 표현됩니다!!)
그리고 예시입니다. 실제 코드 아닙니다.
```c
struct OpenGL_Context {
    ...
    object_name* object_Window_Target;
    ...     
};
```

객체 사용 순서 *예시*

```c
// 객체 만들기
unsigned int objectId = 0;
glGenObject(1, &objectId);
// 컨텍스트에 객체를 바인딩하고 할당
glBindObject(GL_WINDOW_TARGET, objectId);
// 현재 GL_WINDOW_TARGET에 바인딩된 객체의 옵션 설정
glSetObjectOption(GL_WINDOW_TARGET, GL_OPTION_WINDOW_WIDTH,  800);
glSetObjectOption(GL_WINDOW_TARGET, GL_OPTION_WINDOW_HEIGHT, 600);
// 컨텍스트 대상을 기본값으로 되돌리기
glBindObject(GL_WINDOW_TARGET, 0);
```

하나씩 해석해볼까요?

```c
unsigned int objectId = 0;
glGenObject(1, &objectId);
```

unsigned int = uint라고 생각하시면 됩니다.
다른 언어(Rust 등)에서 u16, u32 할때 그 u에요.
부호가 없는 정수입니다.
아무튼 오브젝트를 생성하고, id에 이름을 저장합니다.

```glBindObject(GL_WINDOW_TARGET, objectId);```

objectID 주소에 객체 이름이 들어있었으니, 그걸 타겟에 바인딩합니다.

```c
glSetObjectOption(GL_WINDOW_TARGET, GL_OPTION_WINDOW_WIDTH,  800);
glSetObjectOption(GL_WINDOW_TARGET, GL_OPTION_WINDOW_HEIGHT, 600);
```

설정을 하는 코드네요. 창의 크기를 800x600으로 설정합니다.

``` glBindObject(GL_WINDOW_TARGET, 0); ```

언바인딩합니다. 마무리도 깔끔하게!

이게 흐름입니다.

어렵지요? 정상입니다.
저도 엄청 어려웠습니다.

### 객체의 장점

객체를 사용하면 여러 개의 객체를 만들어 따로따로 설정할 수 있고, 원하는 객체를 필요할 때마다 바인딩하여 사용할 수 있습니다.
그리고 객체 써도 긴데 객체 안쓰면..?
